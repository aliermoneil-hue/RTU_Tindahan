# Every page at 360 pixels (UX-01)

UX-01 asks that every function be usable on a phone browser at **360 px** wide,
with no sideways scrolling of the page. This is the measurement, and the pages it
was run against.

## How it was measured

Chromium, emulated at **360 × 740, DPR 2, mobile**, against the dev build of the
frontend at `#/<route>`, signed in as a member and then as a moderator. For each
route the check is:

```js
document.documentElement.scrollWidth === document.documentElement.clientWidth  // 360 === 360
```

and a sweep for any element whose right edge passes the viewport, excluding SVG
internals, to see *what* is wide when something is.

A wide element is only a defect if its container clips instead of scrolls. Two
kinds were found and both are correct:

- **Category chips** (`.browse-chip-row`) — `overflow-x: auto` at 328 px wide, so
  the row of categories scrolls sideways *inside* the page, which is the pattern
  the design uses on purpose.
- **The store stock ledger table** (`.scroll-x`) — the same: a table wider than a
  phone scrolls within its card. A table that instead shrank to 360 px would be
  unreadable, and one that clipped would hide stock counts.

## The result

Twenty-five routes, all `scrollWidth === 360`:

| Signed in as a member | Signed in as staff |
| --- | --- |
| home, browse, marketplace, store, cart, orders, messages, forum, favorites, shop, profile, help, create, student-sellers, chat, privacy | moderation, baoorders (store orders), baostock (store inventory), forum-reports, message-reports, administrator, transactions, screening-rules, appeals, staff |

Two pages were checked without an account, because that is how a visitor meets
them: the privacy notice and the sign-in page (which advertises the notice next to
the form). The sign-up form's consent line, the product page, the order page and
the moderation panel were also opened at this width while the checks above ran.

## What is left as a cosmetic note

The top bar's search field carries a placeholder that truncates at 360 px ("Sea…").
It does not scroll the page and the field still works; making it a search icon that
opens a sheet would be the design answer, and it is a design choice rather than a
defect. Recorded here so nobody re-discovers it and thinks it was missed.

## Reproducing it

    cd frontend && npm run dev -- --host 127.0.0.1 --port 5173
    # in a browser devtools console, after signing in:
    #   Device toolbar → 360 × 740 → visit each route
    #   document.documentElement.scrollWidth   // must equal clientWidth

The sweep used for the table above is a dozen lines of the same expression over a
route list; it needs no test framework, because the assertion is one number per
page.
