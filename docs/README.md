# docs/

Approved project documents live here so the whole team reads the same version.

Suggested contents, copied from the CapStone folder:

    docs/
    ├── SRS-RTU-Tindahan-v2.0-Complete.md   Software Requirements Specification
    ├── RTU-Tindahan-Tech-Stack.txt         Approved technology stack
    ├── SRS_Gap_Analysis.md                 Gap analysis between SRS versions
    └── diagrams/                           Figma exports, ERD, architecture

## Guides written by the team

- `EMAIL-SETUP.md` — sending verification mail: Mailtrap for local testing,
  Gmail for the deployed backend, plus troubleshooting and rotation rules.
- `AUTH-HARDENING.md` — password reset by code, token lifetime, and ending
  sessions, with the migration path for each.
- `SCREENING.md` — the content-screening boundary: provider rules, the
  deterministic stub, and the moderator queue.
- `POSTING-AND-SELLING-GUIDELINE.md` — the panel's posting and selling rules
  in Markdown, each one mapped to where the system enforces it.
- `POSTGRES.md` — the approved database, the switch in settings, and the
  proof that migrations and the full suite pass on PostgreSQL 16.
- `INTEGRATION-SETUP.md` — connecting the React app to the Django API.
- `BACKUP.md` — the nightly verified database copy (database plus uploads),
  the restore procedure, and the drill that proved a copy by reading it back
  through the ORM.
- `MESSAGE-REPORTS.md` — MS-04 and MS-05: who may report a conversation, the one
  message a moderator is allowed to read, and who is deliberately told nothing.
- `APPEALS.md` — the appeal flow behind AI-06 and RM-08: what can be appealed,
  the separation rule that stops a moderator reviewing their own decision, the
  suspended-account path, and the endpoints.
- `DATA-RETENTION.md` — the retention period behind PR-05: which setting
  governs what, what the nightly purge deletes, what it never touches, and the
  default chosen while the University confirms the number.
- `REQUIREMENTS-TRACE.md` — each requirement ID this repository cites, the file
  that enforces it, the surface to touch, and the test that would fail if it
  stopped being true.
- `DEMO-RUNBOOK.md` — the eight-minute demonstration: pre-flight checks, what
  each role should show, what to say, and what to do when a step misbehaves.
- `SRS-STATUS.md` — every requirement in the SRS with its status in the running
  system, generated by `scripts/srs_matrix.py` from
  `reference/SRS-v1.3-FIXED.md`. Regenerate after an SRS revision.
- `reference/` — the team's SRS (v1.3) and the SRS gap analysis, so the
  requirement matrix can be checked against the source rather than a summary.

Rules:

- Markdown is preferred over `.docx` so changes show up in pull request diffs.
- Keep one current version of each document. Move old versions to
  `docs/archive/` rather than deleting them.
- Never put survey responses with respondent names in this repository unless
  the team has agreed it is necessary.
